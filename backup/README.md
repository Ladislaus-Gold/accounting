# Резервная копия структуры Accounting

Снимок от 2026-11-06. Здесь только структура и код: **ни данных, ни токенов, ни секретов**.
Репозиторий публичный, поэтому свои данные (операции, счета) сюда не кладём.
Данные выгружаются кнопкой в приложении (Ещё → Резервная копия) и хранятся у тебя.

| Файл | Что внутри |
|---|---|
| `schema.sql` | Таблицы, индексы, ограничения, RLS-политики, view `account_balances`, функции |
| `cron.sql` | Расписание опроса Monobank (`mono-poll` каждые 2 мин, `mono-balance` каждые 30 мин) |
| `edge-function-mono.ts` | Код Edge Function `mono` (вебхук и опрос Monobank) |

## Как поднять с нуля

1. Новый проект Supabase. Вход через Google: Authentication → Providers → Google, redirect на адрес приложения.
2. В `schema.sql` заменить uuid `87c04c71-67ca-4fc4-bfb4-c9c3cf451ae9` на свой `auth.uid()` в новом проекте (войти один раз, посмотреть в Authentication → Users). Выполнить файл в SQL Editor.
3. Задеплоить `edge-function-mono.ts` как функцию `mono`, в настройках функции выключить Verify JWT.
4. Загрузить данные из файла резервной копии (JSON или CSV по таблицам).
5. В приложении: Ещё → Monobank, вставить токен заново (токен и секрет вебхука в копию не попадают). Приложение само создаст расписание из `cron.sql`.
6. В `index.html` поменять адрес проекта и публичный ключ Supabase.
